# OVERVIEW (grows with each item)

## Goal
Audio/video file -> offline Whisper -> timed cues -> translation -> SRT / VTT / TXT. All languages.

## Architecture
- `media/` is the module. It touches nothing global except `window.MediaTranslate`.
- `shell/` is a thin standalone host. In MAKAN Translate, the main app plays the host role.
- Module <-> host talk only through the `host` object passed to `MediaTranslate.mount(rootEl, host)`.

## API (item 1)
`MediaTranslate.mount(rootEl, host)` returns a Promise of `{ el, refresh(), unmount() }`.

Host (item 1): `host.t(key)` required; `host.getLang()` optional ('en' | 'fa').
Later items add: `translateCues`, `getWhisperChoice`, `onModelUsed`, `toast`, `saveFile`, `getLanguages`, `desktop`.

## Cue format (same as the Subtitle tab)
`{ s: startSeconds, e: endSeconds, o: originalText, t: translatedText }` - `t` is an empty string when not translated.

## Rules
- CSS: every selector starts with `.mt-`, colours via variables with fallbacks.
- i18n: every key starts with `media`.
- No CDNs, no analytics, no remote scripts. API keys are never printed or stored by this code.

## Item 2 additions
- New module file `media/media-file.js`: pure helpers (`MediaTranslate.file`): `classifyFile`, `formatSize`, `formatDuration`, `needsBigWarning`. Must be loaded before `media-ui.js` (index.html and the host page).
- `handle` now also has `getFile()` (the chosen File or null), `getState()` and `clear()`.
- Optional `host.limits = { maxBytes, maxSeconds, metadataTimeoutMs }` (defaults: 500 MB, 3600 s, 10000 ms). Mainly for tests.
- Big-file warning triggers STRICTLY above 60 minutes or 500 MB. Cancel keeps whatever file was loaded before.
- Test fixtures (`tests/fixtures/*.wav`) are generated by `tests/support/make-media-fixture.js` in Playwright's global setup; they are not committed.

## App design (standalone shell)
- The shell now looks like MAKAN Translate: sidebar (CREATE: Translate, Subtitles, Documents, Voice, Screen, Media; SYSTEM: Games, Model Hub, Settings), top bar with page title, search (Ctrl+K), language switch and settings gear. Dark navy theme, EN/FA, RTL.
- Only the Media page is real. Other menus show an honest placeholder ("part of the full MAKAN Translate app"). Model Hub and Settings get real content in later items.
- Routes are `#/media` etc. The module stays mounted while another page is shown, so a loaded file is not lost.
- The module no longer draws its own title/subtitle/background. The HOST shows `mediaTitle` and `mediaSubtitle` in its page header (the shell does this). The module's root is transparent and uses the host's CSS variables.
- The storage card shows the browser's real storage numbers (navigator.storage.estimate), not disk space.

## Item 3: decode
- New module file `media/media-decode.js` (`MediaTranslate.decode`). Load order in the host page: media-i18n.js, media-file.js, media-decode.js, media-ui.js. `mount()` fails loudly if one is missing.
- `decode.decodeFile(file, { signal, onProgress })` -> `{ samples: Float32Array (16 kHz mono), sampleRate: 16000, duration, sourceChannels, sourceFrames }`.
  1. read the file in chunks (progress, cancel between chunks); 2. `decodeAudioData` on a 16 kHz `OfflineAudioContext` (the browser resamples); 3. average all channels to mono block by block (progress, cancel between blocks).
- Errors always have `.code`: `aborted` (name AbortError) | `unsupported` | `memory` | `read` | `empty` (name DecodeError). `decode.errorKey(code)` gives the i18n key. mkv/avi the browser cannot decode -> "Open this in the Windows app with ffmpeg, or convert to mp4/mp3."
- Memory: raw file buffer and AudioBuffer are dropped as soon as possible; the caller calls `decode.releaseResult(result)` when done (the UI does this when the file changes, is removed, or the tab unmounts).
- UI: info card has a "Prepare audio" button (temporary; item 4's Transcribe will call decode itself), progress bar with Cancel, ready text, error box. `handle.getAudio()` returns the prepared result or null.
- Cancel of the browser's own decodeAudioData cannot stop it, but the call returns at once and its late result is dropped.

## Item 4: Whisper in a worker, Model Hub
Module files (copy into MAKAN Translate): `media/media-worker.js` (the Web Worker), `media/media-asr.js` (`MediaTranslate.asr`, runs on the page). Load order: media-i18n.js, media-file.js, media-decode.js, media-asr.js, media-ui.js. `media-asr.js` is optional: without it (or without `host.getWhisperChoice`) there is no Transcribe card.

How a run works:
1. The decoded 16 kHz audio is cut into windows of about 5 minutes. A cut is placed at the quietest 0.1 s in the last 30 s of a window, so words are not split. If less than 1.2 windows remain, the rest is the last window.
2. Windows go to the worker one by one. The worker loads the model once and keeps ONE model in memory (loading another evicts the first). The language is detected from the first window (1 generated token, like MAKAN Translate) and reused for the later windows, unless the user picked a language.
3. Segments `{ s, e, text }` come back with times relative to the window; the controller adds the window start. A missing end time becomes the end of the window.
4. Cancel ends the worker at once. Finished windows are kept (`handle.getTranscript()` has `partial: true`).
5. If the worker dies or runs out of memory, it is ended and recreated and the same window is tried ONE more time. A second failure shows the friendly memory message and keeps the finished windows.

Host contract added in item 4 (all optional; the Transcribe card needs `getWhisperChoice`):
- `host.getWhisperChoice()` -> `{ repo, name, memMB, ready, gpu? }` or null. `ready === false` means "not downloaded" (the card says so and does not start).
- `host.engine` -> `{ libUrl, workerFactory? }`: the address of Transformers.js. The module has no internet addresses at all; the worker gets `libUrl` in its first message and only accepts https:// or a localhost address.
- `host.onModelUsed(repo)` is called when the model is loaded for a run. `host.openModelHub()` lets the "Open Model Hub" button work. `host.getLanguages()` fills the language list.
- `host.limits.asrWindowSec` changes the window length (tests only).
- Handle: `getTranscript()` -> `{ segments:[{s,e,text}], lang, model, device, partial }` or null. Item 5 turns segments into cues `{s,e,o,t}`.
- WebGPU: the worker uses it only if the spec has a `gpu` setting (a dtype string, or `{encoder_model, decoder_model_merged}`) AND the browser has WebGPU. The GPU files may live in another repo (`gpuRepo`). On any failure it falls back to WASM (q8, the files Model Hub downloads) and reports why as `gpuNote`. The standalone app asks for the GPU by default (Model Hub switch, `localStorage` key `mtUseGpu`); the settings are in `shell/models.mjs` (`GPU_SPECS`), taken from the Transformers.js WebGPU examples and NOT verified by a test.

Standalone-only (not copied at merge): `shell/engine-config.mjs` (the ONLY file with internet addresses: Transformers.js 3.8.1 from jsDelivr, Hugging Face host, cache name), `shell/models.mjs` (the four Whisper models: sizes, memory, file lists, same as MAKAN Translate's catalog), `shell/model-store.mjs` (what is downloaded / download with progress and cancel / delete, in Cache Storage `transformers-cache` under the same addresses the library reads), `shell/modelhub.mjs` (the page). At merge, MAKAN Translate's own Model Hub and `host.whisper` replace these.
- Download skips files already stored, so Cancel and failures continue where they stopped. Delete asks twice (second click within 4 s).
- The chosen model is kept in `localStorage` key `mtWhisperChoice`. Default: Whisper Small.
- To go fully offline later: copy the library and its .wasm files into the app and point `libUrl` at the local copy. Nothing else changes.
- "Prepare audio" button from item 3 is still there. Transcribe prepares the audio by itself when needed.

## Item 5: cue builder
- New module file `media/media-cues.js` (`MediaTranslate.cues`, pure functions, no DOM). Load it before `media-ui.js` (optional: without it there are no cues and `handle.getCues()` is null).
- `cues.buildCues(segments, opts)` takes `[{ s, e, text }]` and returns cues `[{ s, e, o, t }]` (`o` has "\n" between the lines, `t` is ''). Options: `maxLines` 2, `maxChars` 42, `minDur` 1, `maxDur` 7, `repeatRun` 3, `repeatWords` 4, `silenceRms` 0.002, `samples` (16 kHz mono Float32Array, optional).
- The ten rules are written at the top of `media-cues.js`: clean, collapse repeats, split at sentence/comma/space, wrap into 2 lines, share the time by length, skip silence (needs samples), fix overlaps, make too-short cues longer or merge them, cut to 7 s, round to ms.
- A cue can stay shorter than 1 s only when it can neither be stretched (next cue too close) nor merged (the text would need 3 lines).
- The Transcribe card shows "Subtitle lines: N". `handle.getCues()` gives copies of the cues (null if nothing was recognised or media-cues.js is missing); `getState().cueCount`.
- The silence check uses the decoded audio of the same run, so it only drops cues whose whole time span is quieter than RMS 0.002.

## Item 6: translation
Module part (copied at merge): the "Translate subtitles" card in `media/media-ui.js` + `media-tab.html`, `media.css`, the `mediaTr*` / `mediaErrTr*` strings. Standalone part (replaced at merge by MAKAN Translate's own engines): `shell/engine-adapter.js`, `shell/translate-worker.js`, `shell/translate-models.mjs`, `shell/translate-setup.mjs`, `shell/engine-online.mjs`.

Host contract added in item 6 (the card appears only when `translateCues` exists and there are cues):
- `host.translateCues(cues, { src, tgt, onProgress, signal, onInfo }) -> Promise<cues>`
  - `cues` are `[{ s, e, o, t }]`. The result is a NEW array with the same length and order; `s`, `e`, `o` unchanged, `t` = translation. Cues with no text keep `t = ''`. The input is never changed.
  - `onProgress({ stage:'load'|'translate', fraction, done, total, engine })`; `onInfo({ id, kind:'offline'|'online', name, model?, repo?, licence?, device? })` tells which engine/model is translating. The card shows it, so the label is always honest.
  - `signal` cancels. Errors carry `.code` (`aborted | nokey | badkey | notdownloaded | unsupported | memory | engine | network | rate | badreply | failed`) and `.partial` (cues finished so far, kept by the card).
- `host.getTranslateChoice()` (optional) -> `{ name, kind, model?, licence?, licenceNote?, ready?, needsKey? }`: what will translate, before the user presses the button. `needsKey` or `ready === false` disables the button and says why. `licence` / `licenceNote` are shown next to the engine.
- `handle.getCues()` returns the translated `t`; `getState()` adds `trStatus`, `trErrorKey`, `translatedCount`.

How the standalone adapter works:
- Offline (`nllb`, `m2m100`, `mbart`): a second worker (`translate-worker.js`) with the same rule as Whisper: ONE model resident (loading another disposes the first), only `owner/name` repos, library address sent in the first message, always WASM q8 (the files Model Hub downloads). Cues are sent in batches of at most 8 texts / 1200 characters, each cue on one line. Our language codes are mapped per model (`translate-models.mjs`); a language the model has no code for is "unsupported" (nothing is guessed). Translated text is re-wrapped to at most 2 lines of 42 characters when the original had 2 lines or the translation is longer than one line.
- Same failure rules as Whisper: a dead or out-of-memory worker is replaced and the batch tried once more; a second failure keeps what is finished. Cancel ends the worker at once.
- A model that is not downloaded stops with "not downloaded" (it is never downloaded silently).
- Gemini (optional, online): the person pastes THEIR OWN key in Model Hub. The key lives in one variable in memory: not in localStorage/sessionStorage/cookies, not in the page, not in any message. It is gone on reload. It travels only in the `x-goog-api-key` request header. Cues go in batches of 40 as a JSON array; a reply with the wrong number of items is split in halves and asked again. If the default model name does not exist for the key, the adapter asks the key for the newest plain "flash" model and the label shows the name it really used. The only address is in `shell/engine-online.mjs`.
- Honest labels: the card shows "Engine: NLLB-200 600M (offline, on this computer)" or "Engine: Gemini · model (online)" with "The subtitle text is sent to Google".
- Licences: NLLB-200 is CC BY-NC 4.0 (non-commercial only): the licence and a note are shown on its Model Hub card and in the Translate card. M2M-100 and mBART-50 show MIT.
- Model Hub now has three sections: speech models, translation models (own class prefix `sh-tr-`, so the Whisper list is unchanged) and the Gemini card. The offline choice is kept in `localStorage` key `mtTranslateChoice` (default NLLB); the Gemini choice is never kept.

## Item 7: preview and export
- `media/media-export.js` (`MediaTranslate.exporter`): pure functions, no DOM. `srt`, `vtt`, `txt` take `(cues, mode)` with mode `original`, `translated` or `bilingual`; plus `fmtTime`, `escapeCue`, `textOf`, `toBlob`, `baseName`, `safeName`, `fileName`.
- `media/media-preview.js` (`MediaTranslate.preview.create({card, host})` -> `{update, destroy}`): the "Preview and export" card. The module calls `update()` from `render()`; the list is rebuilt only when the module raises a cue version number.
- Player: `<video>` or `<audio>` from one object URL. It is revoked when the file is cleared or replaced, when the cues disappear, and on unmount. One live subtitle track (`addTextTrack` + `VTTCue`) shows the original or the translation, chosen in "Show".
- List: the time button (or the text) jumps the player to that cue. Edit opens a text box; Ctrl+Enter saves, Esc cancels, leaving the box saves (it closes 0.2 s later so a click on a lower button is not lost). Edits change the cue in place (`o` in Original view, `t` in Translation view), so `getCues()` and every export see them.
- Files: Original SRT, Translated SRT, Bilingual SRT, VTT and TXT (the last two follow "Show"). Names: `<file>.<lang>.srt`, bilingual `<file>.<src>-<tgt>.srt`. SRT and TXT get a UTF-8 byte-order mark and CRLF so Windows players read Persian; VTT has none. Cues with no text are skipped and numbering restarts at 1. Saving goes through `host.saveFile(name, blob)`; without it the buttons are hidden.
- Not-translated lines: Translated SRT leaves them out, Bilingual keeps their original, the list shows the original in grey with a note.
- `getState()` adds `pvVisible`.

## Item 8: Windows app and ffmpeg
- Run it: `npm install` once (adds Electron), then `npm run desktop`. Portable exe: `npm run dist` (output in `dist/`). Setup program with uninstaller: `npm run installer` (NSIS; icon in `build/`). User guide page: route `#/guide`, texts `shellGuide*` in `shell/shell.js` (EN + FA), drawn by `paintGuide()`. `npm start` is still the plain web server.
- `desktop/main.js` (Electron): starts a local server on 127.0.0.1 (ports 47215-47222, always the first free one, so the browser storage with the downloaded models is found again), opens one window. Page isolation is on, Node is off, sandbox is on, no new windows, no leaving the local address. Every request from the page is answered only when it comes from that address.
- `desktop/preload.js`: gives the page ONE object, `window.MTDesktop` (find/choose ffmpeg, path of a dropped file, extract, cancel, read chunk, release, save next to the file). No file system or Node for the page.
- `desktop/ffmpeg-bridge.js` (plain Node, tested with fake files and a fake process): finds ffmpeg (chosen path, then next to the app, then PATH; ffmpeg is NOT included), turns a media file into 16 kHz mono 16-bit raw audio in a temp file with an argument array and no shell, reports progress, returns the audio in chunks, deletes the temp file (also on cancel, error, quit, and old leftovers at start). Saves subtitle files next to the media file without ever overwriting.
- `desktop/static-server.js`: serves only `index.html`, `media/` and `shell/`.
- `shell/desktop-host.js`: turns `window.MTDesktop` into `host.desktop` for the module: `ffmpeg()`, `chooseFfmpeg()`, `extractAudio(file, {signal, onProgress, seconds})`, `saveNextTo(file, name, blob)`. Audio is read in 4 MB pieces and turned into floats piece by piece, so only the final array (4 bytes per sample, about 154 MB for 40 minutes) is held.
- Module behaviour with `host.desktop` (the module never names `MTDesktop`): an ffmpeg card shows whether ffmpeg is found and offers "Choose ffmpeg…"; with ffmpeg, Prepare/Transcribe use `extractAudio` instead of the browser decoder (any file type, long files); the size warning is off (a 3-hour time limit stays); a file the browser cannot read without ffmpeg shows "This file needs ffmpeg"; the export card gets "Save next to the media file" (falls back to a normal download if that fails).
- Without ffmpeg, or in a plain browser, everything works as before.
- Known limits: the whole 16 kHz audio of a file is held in memory for transcription (about 3.8 MB per minute), and the speech engine speed on long audio depends on the computer.

## Speed (CPU threads and GPU)
- Several CPU threads need a cross-origin isolated page. Both local servers (`tests/support/static-server.js` for `npm start`, `desktop/static-server.js` for the Windows app) send `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: credentialless`. Without them the engine uses ONE thread.
- Both workers set the thread count to `min(8, cores - 2)` (at least 1; 1 when the page is not isolated). The `load` reply carries `threads`.
- Whisper can use the graphics card (WebGPU), see the WebGPU note above. The offline translation models (NLLB, M2M-100, mBART) use the CPU only: their quantized files do not run reliably on WebGPU. For GPU translation use Ollama (TranslateGemma), which uses the graphics card by itself.
- If you start `npm start` yourself before `npm test`, stop it first: the tests start their own server with the headers.

## Engines, step 1: the core (`shell/tr-core.js`)
Pure building blocks for the new translation engines (standalone only; at merge MAKAN Translate has its own). Adds only `window.MTShell.trCore`; no network, no storage of its own, never sees a key.
- `LANGS` / `langInfo(code)` / `shortCode(code)`: one table, app language -> display name + code (`zh` -> `zh-CN`, `pt` -> `pt-BR`). A test checks it against the shell's language list.
- `protectCue(text)` / `restoreCue(translated, prot)` / `hasText(prot)`: tags (`<i>`, `{\an8}`), music notes and speaker dashes are taken off each line before translating and put back after; line breaks stay. Tags inside the text become markers `⟦n⟧`; if a marker is lost the inner tags are dropped (never a lone `<i>`). If the engine changes the line count, the first prefix and last suffix are kept.
- `createMemory({store,key,max})`: translation memory keyed by source text + src + tgt, oldest dropped at `max` (5000), `save()` writes to the given store (resume after a crash = the same cues are answered from memory).
- `dedupe(texts)`, `batchByBudget(texts, {maxChars,maxItems})`, `BUDGETS` / `budgetFor(id)` / `pacingDelay(id, random)`: each different line once; batches by engine (Google 1800 chars / 40 lines, MyMemory 450 / 1, Gemini 40, offline 6, Ollama 15, TranslateGemma 10); concurrency 1; a small random pause.
- `createCooldown({now})`: 30 s, then 2 min, then 10 min per engine; `parseRetryAfter(value, now)`; `backoffDelay(attempt, {baseMs,capMs,random,retryAfterMs})`.
- `failureReason({status,contentType,text,error,timedOut})` -> `rate | blocked | server | timeout | network | html | http | null`; `checkReply(inputs, outputs)` -> `count | empty | null`.

## Engines, step 2: the fallback chain
Standalone only (`shell/engine-chain.js`, `shell/engine-order.mjs`, wiring in `shell/shell.js`). Same contract as `host.translateCues`; nothing changes for the module except optional extra fields in `onInfo`.
- Engine = `{ id, name, kind, model?, licence?, budgetId?, translate(lines[], {src,tgt,signal,onInfo,onProgress}) -> Promise<string[]> }`. `wrapAdapter` turns the existing engines (NLLB, M2M-100, mBART, Gemini) into chain members; later engines (Ollama, Google, ...) are written as engines directly.
- `create({getEngines,getOrder,memory,cooldown,...}).translateCues(cues, o)`: protects tags and line breaks, answers repeated lines from the memory, sends the rest in batches (budgets in `tr-core.js`) to the first engine in the user's order that is not resting. A failure (429/403/5xx, HTML reply, wrong count, empty answer, timeout, network) makes the engine rest (30 s, 2 min, 10 min; a longer Retry-After wins) and the SAME batch goes to the next engine. An engine that can never work for the job (`nokey`, `badkey`, `unsupported`, `notdownloaded`) is skipped for the rest of the job. If every engine rests it waits for the first to be ready. Cancel works at any time; the finished cues come back as `error.partial` and are already in the memory.
- `onInfo` extras (all optional for hosts): `switched: {from, reason}`, `used: [{id,name,count}]`, `waitingMs`. The module shows them ("X stopped (why). Now using Y.", "Translated by: …", "All engines are resting…"). `onBatch({engine,name,count,done,total})` tells which engine did each batch.
- The memory (`localStorage` key `mtTrMemory`, at most 5000 lines, original-language words only) lives on this device. Model Hub shows its size and has "Clear saved translations". The chain state is `mtEngineChain` = `{on, order, off}` (engine ids only). The chain is OFF by default: then the single engine chosen in Model Hub is used exactly as before.

## Engines, step 3: Ollama and TranslateGemma
- `shell/tr-llm.js`: pure helpers for language-model engines (official TranslateGemma prompt, `<<<n>>>` batches, quote/label cleaning, JSON-array answers with exact count, retry then one cue per request).
- `shell/engine-ollama.js`: talks to Ollama on this computer only (`127.0.0.1:11434`, then `localhost:11434`). Models whose name contains `translategemma` use `/api/generate` with the official prompt; other models use `/api/chat` and a JSON array. Always `stream:false`, `keep_alive:"30m"`.
- `shell/ollama-card.mjs`: the Ollama card in Model Hub. Nothing is contacted when the page opens; the card looks for Ollama only when Refresh is pressed (and when a translation starts). The chosen model is kept in `mtOllamaModel`, "in use" in `mtOllamaUse`.
- Ollama joins the fallback list only after a model is chosen. "Ollama not running" and "model not installed" end Ollama's turn for that job and the next engine continues the same batch.
- Messages: "Ollama is not running" and "run: ollama pull <model>" (English and Persian).
- Not verified on a real machine: Ollama's browser access rules when the app is served from another website (the standalone Windows app should work; a merged web page may need `OLLAMA_ORIGINS`).

## Engines, step 4: LM Studio and other OpenAI-style servers
- `shell/engine-openai.js`: engine for any program with the common OpenAI-style web address (LM Studio default `localhost:1234/v1`, built from parts). `GET /models` fills the picker; `POST /chat/completions` (stream false, temperature 0.2) asks for a JSON array with exactly N strings; wrong count is retried once, then cue by cue (shared code in `shell/tr-llm.js`).
- Errors: no answer -> `notrunning`, 401/403 -> `badkey`, 429 -> `rate` with `retryAfterMs` from Retry-After, missing model -> `nomodel`, 5xx -> `failed` (reason `server`).
- `shell/openai-card.mjs`: Model Hub card with address, optional key (memory only, sent only as a Bearer header to the typed address, never stored), model picker, Refresh, Use. Nothing is contacted when the page opens. Saved: `mtOpenaiBase`, `mtOpenaiModel`, `mtOpenaiUse`.
- The engine counts as "offline" when the address is on this computer or a private network, otherwise "online".
- Only one single-engine choice (Ollama, this server, Gemini or an offline model) is active at a time; in the fallback chain each joins the list after a model is chosen.
- Not verified on a real machine: LM Studio's CORS setting ("Enable CORS" must be on for a browser page to reach it).

## Engines, step 6: honest labels, exported note, help
- Engine list hints: offline models say "free · on this computer", NLLB adds "non-commercial licence (CC BY-NC 4.0)", Gemini "online · your own key", Ollama and servers "free · local program", Google "Fast - unofficial - may stop", MyMemory "free · online · small daily limit", Chrome "free · on this computer · Chrome only".
- The "text is sent online" warning names the engine (Gemini keeps its Google wording; a list of engines says some are online).
- Exported VTT after a translation ends with `NOTE Translated by <real engine names, model when one engine>`. It is placed after the last cue so the file still starts with the cues. SRT and TXT have no comment syntax, so they stay clean. Original-language exports have no note.
- A Help section in Model Hub: install Ollama and `ollama pull translategemma:4b`, LM Studio CORS, the web translators' limits, and that keys stay in memory only.

## Engines, step 5: free web translators
- `shell/engine-web.mjs` is the only file with their addresses (Google's two unofficial addresses and MyMemory). `shell/engine-free.js` has the engines; `shell/free-card.mjs` is the Model Hub card. All three are OFF until the person allows them, they are never the default, and nothing is contacted when the page opens.
- Google Translate (web): label "Fast - unofficial - may stop". One POST with many lines to the first address; if that fails (blocked, HTML/captcha page, wrong length, no answer) it asks the second address one line at a time. Too many requests (429) is reported as `rate` with Retry-After and the second address is not hammered. Unofficial: Google can change or block it, and a browser page may be refused by the server (cross-origin rules) - unverified here.
- MyMemory: one line per request, optional email for a bigger daily limit (kept in `mtMyMemoryEmail` on the device only). A used-up limit is `rate` with a 10-minute rest.
- Chrome on-device Translator: shown only when the browser has `Translator`. Needs both languages chosen. If Chrome cannot start the language pack it reports `notdownloaded` (the chain skips it for that job).
- Allowed engines join the "several engines" list at the end (`mtWebEngines` holds which are allowed). Pacing, cool-down, switching messages and the translation memory come from the chain (steps 1-2).
- Tests 02 and 06 know about `engine-web.mjs` (02 skips it; 06 expects two files with "googleapis": the Gemini one and this one, and that this one never names Gemini). `15-free-engines.spec.js` checks it strictly: exactly three addresses, nothing else.

## Subtitle style menu (preview and files)
- In the Preview card: font (6 English, 7 Persian-capable, all fonts that ship with Windows or are common; one that is not installed falls back to the next in its stack), size 14-48 px, text colour (24 swatches plus a free colour picker) and background (dark / black / light / none), with Reset.
- It is stored as four CSS variables on the card (`--mt-cap-font`, `--mt-cap-size`, `--mt-cap-color`, `--mt-cap-bg`). An audio file gets a caption box under the player (an audio element draws no subtitles itself) that shows the line playing now, or a sample line when idle. A video keeps the player's own subtitles, styled through `::cue` with the same variables (the browser decides how much of the style it honours).
- Files: SRT gets `<font face color>` on every line (only values that differ from the defaults), VTT gets a `STYLE ::cue` block (font, size, colour, background) before the cues, both while "put my font and colour into the files" is ticked (default); a new ASS button always writes the full style (font, size, colour, box or outline). ASS size = preview px x 1.5 on a 1280x720 script; the box uses the background colour. TXT stays plain. Exporter: `srt(cues, mode, style?)`, `vtt(cues, mode, note?, style?)`, `ass(cues, mode, style?, note?)`; with no style the output is identical to before. Players decide how much of it they show (VLC and MPC-HC follow SRT colour and ASS; Windows Media Player and some others ignore it). No burn-in into video.
- Remembering: the module never touches storage. A host may offer `loadSubtitleStyle()` / `saveSubtitleStyle(style)`; the standalone shell keeps it in `mtSubStyle`. Without them the style lasts until the page is closed. Style shape: `{ font, size, color, bg }`; bad saved values are replaced by the defaults.
